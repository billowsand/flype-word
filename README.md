# flype-word

一个用 Rust 编写的小鹤双拼词库生成器。流程刻意分成两条命令，中间留出人工修订环节：

1. `extract`：用 jieba 分词，统计词频并导出 TSV。
2. 人工删除误词、增加漏词、调整顺序，必要时校正多音字拼音。
3. `encode`：按照四码定词规则生成 `词语<TAB>编码` 码表。

项目同时提供基于 egui/eframe 的 Windows 图形界面，适合直接完成上述三步。

## 图形界面

开发环境中启动：

```powershell
cargo run --bin flype-word-gui
```

发布构建后直接运行：

```powershell
.\target\release\flype-word-gui.exe
```

界面分为三个页面：

1. **原文与分词**：打开或粘贴中文原文，设置最低词频、单字选项、HMM 和 jieba 用户词典。原文框可滚动，粘贴多少字都不会挤掉下方的按钮；分词在后台线程进行，运行期间显示转圈提示，界面不会假死。
2. **人工修订**：直接编辑词语、词频和多音字拼音，支持搜索、只看错误、增删及调整顺序，也可导入或保存 TSV。上下移动按屏幕上的可见顺序走，因此筛选状态下同样有效。
3. **最终码表**：实时预览最终编码和重码，可复制到剪贴板，导出带 UTF-8 BOM 的小鹤用户码表及重码报告。预览最多显示前 2000 行，导出和复制始终是完整码表。

其它界面约定：

- 打开的文本文件除 UTF-8 外，还会自动回退按 GB18030（GBK/ANSI）、Big5、UTF-16 解码，状态栏会说明实际使用的编码。
- 可以把文件直接拖进窗口：`.tsv` 当作词表导入，其它当作原文打开。
- 导入词表时重复词语会标成行错误留在界面上修改，不会整份文件被退回（命令行的 `encode` 仍然严格拒绝重复词）。
- 词表有未保存的修改时关闭窗口会先询问，可以选择保存后退出。
- 深浅色开关使用 egui 的主题偏好设置，不受系统主题切换影响。

界面字体使用 `font/sfss.ttf`，构建时嵌入 EXE，发布后无需额外携带字体文件。命令行程序仍然保留。

## 构建

需要 Rust 1.85 或更新版本：

```powershell
cargo build --release
```

生成的程序位于 `target/release/flype-word.exe`。

## 第一步：分词和词频

```powershell
cargo run --release -- extract article.txt words.tsv
```

常用选项：

```text
--min-frequency 2   只保留出现至少 2 次的词
--include-single    同时导出单字（默认只导出二字及以上）
--user-dict FILE    加载 jieba 用户词典
--no-hmm            关闭 HMM 新词识别
```

`words.tsv` 按词频从高到低排列：

```text
# 词语  词频  拼音（可选；多音字可填空格分隔的无声调拼音）
小鹤双拼    12
词库        8
重庆        3
```

## 第二步：人工修订

可以删除整行、添加新词或调整顺序。程序接受下面四种行格式：

```text
词语
词语    词频
词语    词频    pin yin
词语    pin yin
```

自动拼音按单字词典中的默认读音生成。多音字建议在最后一列人工标音，例如：

```text
重庆    3    chong qing
音乐    2    yin yue
```

拼音不带声调，音节以空格、逗号或斜杠分隔。每个字必须对应一个音节。

## 第三步：生成编码

```powershell
cargo run --release -- encode words.tsv flypy-user.txt
```

同时生成重码报告：

```powershell
cargo run --release -- encode words.tsv flypy-user.txt --conflicts conflicts.tsv
```

如需与仓库中现有的小鹤用户码表相同的配置头：

```powershell
cargo run --release -- encode words.tsv flypy-user.txt --with-flypy-header
```

最终码表格式为：

```text
小鹤双拼    xhsp
词库        ciku
```

## 编码规则

| 词长 | 规则 | 示例 |
|---|---|---|
| 1 字 | 该字完整小鹤双拼 | `小 → xn` |
| 2 字 | 两字各取完整双拼 | `小鹤 → xnhe` |
| 3 字 | 前两字声母键 + 末字完整双拼 | `计算机 → jsji`、`知识库 → vuku` |
| 4 字及以上 | 前三字和末字的声母键 | `中华人民共和国 → vhrg` |

这里的“声母键”是小鹤双拼键盘上的声母键，和该音节全码的第一键始终一致：`zh/ch/sh` 分别取 `v/i/u`，所以 `知 → v`、`吃 → i`、`上 → u`，其余声母就是拼音首字母本身。零声母音节（`安 an`、`欧 ou` 等）取韵母的第一个字母。

例如 `知识库` 的三个字全码是 `vi`/`ui`/`ku`，按三字规则取 `v` + `u` + `ku`，得到 `vuku`。

零声母音节（拼音以韵母开头）的全码按韵母长度分三种：

| 韵母长度 | 规则 | 示例 |
|---|---|---|
| 1 个字母 | 重复两次该键 | `啊 a → aa`、`哦 o → oo`、`额 e → ee` |
| 2 个字母 | 直接打全拼 | `爱 ai → ai`、`恩 en → en`、`欧 ou → ou`、`儿 er → er` |
| 3 个字母 | 韵母首字母 + 韵母键 | `昂 ang → ah`、`鞥 eng → eg` |

注意这只针对零声母音节；同样的韵母跟在声母后面仍然走键位表，例如 `海 hai → hd`、`给 gei → gw`。

输入输出路径可写成 `-`，分别表示标准输入和标准输出。所有文件输出使用带 BOM 的 UTF-8，方便 Windows 工具直接识别；标准输出使用不带 BOM 的 UTF-8。

## 测试

运行全部单元测试和真实 CLI 端到端测试：

```powershell
cargo test
```

端到端测试位于 `tests/cli_e2e.rs`，使用 `tests/fixtures` 中的真实中文文章、jieba 用户词典和人工修订词表，验证：

- 分词及词频统计；
- 单字、二字、三字和四字以上编码；
- 多音字人工拼音；
- 重码报告；
- 文件 BOM 与标准输入输出；
- 拼音数量错误时拒绝生成不完整码表。

图形界面的测试在 `src/bin/flype-word-gui.rs` 里，用无头 `egui::Context` 直接跑真实界面代码，断言三个页面的内容都不会溢出面板（即按钮和预览不会被顶出窗口）、操作列装得下三个按钮、编码缓存只在编辑后重算，以及编码回退和主题开关的行为。
